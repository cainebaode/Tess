# Tess 正式安装与首次使用方案

日期：2026-10-20。

目标：用户拿到一个正常的 Mac 应用，安装后跟随引导完成第一次语音输入，日常使用无需打开终端、查阅开发文档或理解模型参数。当前 build 12 仍是内部试用版本，先补齐首次使用和真实输入验收，再制作正式安装包。

## 用户安装后应看到什么

| 阶段 | 预期体验 |
| --- | --- |
| 安装 | 下载 `Tess.dmg`，打开后看到 Tess 图标和“应用程序”快捷方式，拖入即可。从“应用程序”启动唯一正式副本。 |
| 欢迎 | 简短介绍“按住快捷键说话，文字直接进入输入框”，提供明确的“开始设置”按钮。沿用现有像素角色，页面语言和按钮保持统一。 |
| 授权 | 逐项解释并请求麦克风、辅助功能权限；从系统设置回来自动检查状态。截图权限在第一次截图时再请求。拒绝后提供明确重试入口。 |
| 准备语音 | 默认只推荐一个基础模型；用户确认下载后显示实际容量、进度、失败原因和重试。高级模型放入设置。基础听写无需 API Key。 |
| 试说 | 检测麦克风、确认快捷键，完成一句真实语音练习。只有实际识别成功才标记该项完成；随后引导在外部输入框验证自动输入。 |
| 使用 | 菜单栏常驻；录音时出现浮层，显示音量和实际中间文字。结束后输出到原输入位置，浮层收起，普通听写不打开结果窗口。 |
| 恢复 | 无输入位置时清楚提示已复制；取消不输出；权限缺失、模型加载或识别失败均有具体下一步。重启后保留设置，引导可继续。 |
| 更新 | 提供版本与更新入口；第一版可采用下载新 DMG 后替换的明确流程，保留模型、配置和历史。自动更新作为后续独立实现。 |

初次推荐暂定 Qwen3-ASR 0.6B，因为项目已有实际推理验证；最终默认选择须通过中文与中英混说的真人样本验收。当前模型来源为 Hugging Face，交付前需验证目标网络可下载；若不能稳定完成，应提供经许可核对的可达下载源或模型随包方案，不能要求普通用户自行解决开发环境问题。

文字整理继续作为可选能力，服务商配置放在基础听写成功之后。设置需明确哪些文字会发送给配置的服务。首次界面不让用户同时面对多家服务商和多个语音模型。

该首次使用顺序参考 [Wispr Flow 官方设置流程](https://docs.wisprflow.ai/articles/3152211871-setup-guide)，其 Mac 流程包含拖入应用程序、权限、麦克风测试、快捷键设置和试说。

## 安装包实现方案

采用站外分发的 DMG。固定应用标识 `life.baode.tess` 和签名团队，启用适合实际运行库的 Hardened Runtime 权限，使用 Developer ID Application 正式签名，完成 Apple 公证并附加票据。用实际下载的安装包验证 Gatekeeper 启动路径。流程依据 [Apple Developer ID 官方说明](https://developer.apple.com/developer-id/)。

本机已检查到有效的 Developer ID Application 签名身份；公证账户访问、运行库兼容性和正式包的验证仍需落实。现有 `scripts/build.sh` 使用临时签名，不能直接作为正式交付流水线。

保留 Apple Silicon、macOS 26+ 的当前支持范围。用户端不需要 Xcode、Metal 编译工具或任何命令行操作。正式包不得包含测试入口、隔离数据和开发演示按钮；设置提供版本、帮助、隐私说明及清理本地数据入口。

## 执行顺序与交付条件

1. **完成首次使用流程。** 空配置启动后，沿着一个连续流程完成授权、模型准备、快捷键和试说；中途退出可继续，拒绝权限或下载失败可恢复。
2. **验证真实输入体验。** 在文本编辑、浏览器输入框和一款实际常用聊天应用中完成中文及中英混说；检查连续多次录音、取消后重开、切换目标、休眠唤醒后的表现。失败须修复后再交付。
3. **制作正式签名与公证的 DMG。** 从真实下载入口进行全新安装，确认没有开发者身份阻断，不需要关闭安全功能；再验证一次覆盖更新后模型和配置保留。

重新交付的标准是“首次安装后能够顺利完成真实听写并进入日常使用”。构建通过、签名通过和公证成功分别记录，均不能代替这条产品验收标准。当前真实输入的剩余问题见 [基础输入验收记录](../history/20261020-01-tess-ux-acceptance.md)。
