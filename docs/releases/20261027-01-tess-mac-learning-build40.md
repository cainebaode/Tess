## 纠正学习

在“设置 → 语音识别”新增默认关闭的“从我的纠正中学习”，与手动常用词开关独立。

| 环节 | 实际行为 |
| --- | --- |
| 结果页 | 保存不可变 ASR 原文、交付文本、来源模式、原目标应用和模型／提示快照标识。编辑约 1 秒后计算多个局部差异，继续编辑或撤销会使旧候选失效。重新加工保留原基线，但排除学习 |
| 主动提交 | 选择当前最近结果，核对原文与时间，主动粘贴对应整段改稿；提交及确认时再次核对结果 ID 和修订号。适用于微信、ChatGPT 兼容输入、仅复制等场景 |
| 候选确认 | 仅纯听写、未经上下文校正或文字加工的结果可生成候选。最多 3 处，每处改前／改后均不超过 32 字；日期、数字、否定、路径、代码、重复歧义、语序调整及大段改写保守排除。最终是否听错由用户确认 |
| 本地记忆 | 确认后保存到 `speech-learning.json`，最多 50 条；满额提示管理，不覆盖已有记录。默认原应用范围，未知应用必须明确选择所有应用。支持停用、改范围、删除、最近一次保存的撤销及清空 |
| 下一次识别 | 录音开始固定一次提示，预览、最终识别和重试复用。手动词优先，合并去重后最多 50 项、2,000 字；超限或冲突有提示。只把正确写法与短说明送给 Qwen，不提供误写映射，不全局替换，不自动加入远端文字校正材料 |
| 关闭与清理 | 关闭立即停止采集并销毁待确认候选，下一次录音不使用学习提示，已确认记录保留。删除和撤销清除相应待处理内容；清空同时移除学习恢复副本。候选只在内存保存，不跨启动恢复 |

同一误写在重叠范围内存在不同纠正时，双方暂停提示；用户可以停用其中一项或调整范围。Whisper 显示“此模型暂不使用个人学习提示”。提示不代表模型经过训练，也不保证后续一定识别正确。

## 外部输入框的适用边界

仅对本次目标的普通可访问输入框，在原粘贴事务中记录插入前文本与 UTF-16 选区，最长 1 秒有限回读。必须能按原选区唯一验证真实插入／替换，才注册这个元素的文本变化通知。兼容窗口目标、复制回退、未实际粘入、重复正文、通知不支持都不建立观察。

观察最长 120 秒，变化防抖约 1 秒；文本读取依赖该元素通知，生命周期看守只检查身份、焦点、权限和时限。字段全文只用于内存定位，超过 8,000 字放弃；观察期间只保留边界长度与摘要，结果仅保存本次听写片段。改动越过范围、字段清空、失焦、元素／窗口／应用变化、权限失效、下一次录音、关闭学习或退出均停止。稳定取得的候选可留在最近结果供确认，迟到回调需匹配观察代次、结果 ID、基线及修订号。

没有全局键盘正文采集、剪贴板轮询、模拟全选复制或 OCR。实际应用是否提供完整 AX 能力仍需人工体验；本轮外部采集的成功／失败分支由隔离夹具验证，不能把 `attemptedPaste` 当作插入成功。

## 模型对照结果

用户明确表示不准备独立真人语料，希望在使用中逐渐积累。本轮积累的是经用户确认的文字记忆；不新增日常录音持久化，因此文字改稿不能自动成为带原始音频的 ASR 评测集。基础模型选择和个人学习的真人准确率均为**未验证**。

复用 build 38 的 8 条 Tingting 合成 WAV，覆盖 PRD、token、语音输入、真正 PLD、“偷看了”“云输入”、事实约束和长句。所有样本明确标记 synthetic／smoke，近重复分组字段、WAV 摘要、参考文本和术语标签写入清单。每个条件单独进程运行，首次识别单列，热推理 3 次；准确率计数只用每条第一次热运行，重复不作为新增语料。系统编译缓存未清空，因此进程首次耗时也不能单独归因于提示效果。

提示夹具由合成词条构成，**不是从真人开发组获得的学习条件 C**。该小组中三项条件均无漏字，普通中文样本无新增错误；提示夹具相对同模型无提示未新增已标注术语／歧义词错误。以上只验证接入与运行差异，不据此宣称准确率改善或达到第 7.8 节门槛。

自动语种无提示／提示夹具的加载时间分别为 0.485／0.484 秒，进程首次识别为 1.619／0.161 秒。10–30 秒录音只有 1 条，其重复测量 p95 为 0.567／0.525 秒，不能推广为日常等待预算结论。

0.6B 使用 `aufklarer/Qwen3-ASR-0.6B-MLX-4bit`，revision `bc441bd1e4295c1f42d9879f056049a925b6e013`，4-bit MLX；权重 SHA-256 和其余文件摘要逐一重新核对收据。Swift 上游版本为 `cbcdfc6be5e723952d29ab6e32af5e22ad8e70fa`，本地实际推理源码摘要和每次提示快照随报告保存。

1.7B 和 Whisper 沿用现有公开仓库、下载器及独立 `.build/models/` 路径尝试准备，模型源连接超时；直连、镜像重定向和系统现有代理的只读连接检查也未成功。本机没有这两组完整权重，不能提供实测精度、内存或延迟。**未推荐更换默认；用户当前 Qwen 0.6B 与自动语种保持原样。**

## 人工验收

1. 开启学习，用 Fn 纯听写；在最近结果改一处真实听错的词，停约 1 秒，核对整句与候选，再点“记住”。继续改稿或还原原文时，旧候选应消失。
2. 在 TextEdit 普通输入框完成一次听写并修改，停止编辑约 1 秒后查看最近结果；微信使用“提交改好的文字”主动粘贴对应整段。确认没有抢焦点、重复插入或自动发送。
3. 查看应用范围，在“已学习内容”试停用、撤销、删除和清空；下一次 Qwen 录音才使用新的提示状态。翻译／润色、改日期数字或改变主意不应自动成为记忆。
4. 简短复查原快捷键、浮窗上滚回看／回到最新、取消和设置保留。识别效果以日常真实反馈判断，不因合成对照记作通过。

## 本机证据与复跑

原始证据位于 `evidence/20261027-mac-learning/`，受 Git 忽略：初始补丁／文件摘要、学习及回归日志、内部构建及源码摘要、synthetic corpus、逐条识别与耗时 JSON、模型校验、下载失败日志、安装和设置核对。最终安装证据为 `installed-build40-verification.json`、`settings-preserved-build40.json`、`release-build40.log` 和 `signing40.log`；完整候选为 `.build/local/0.3.0-build40/Tess.app`，原 build 38 候选保留。没有把用户配置、模型或录音加入源码 Git。

`ASRBenchmark` 仍只在 `TESS_INTERNAL_CHECKS` 构建中启用，交付应用没有内部 CLI。显式传入 `TESS_BENCHMARK_MODELS`、`TESS_BENCHMARK_CORPUS`、`TESS_BENCHMARK_OUTPUT`、`TESS_BENCHMARK_MODEL`、`TESS_BENCHMARK_IMPLEMENTATION_SHA256` 后，以 `--asr-benchmark` 运行；每个样本必须包含 `source`、`split`、`group`，开发／保留分组不得共享原句分组或音频。基线不传词库／记忆；提示夹具另传 `TESS_BENCHMARK_MEMORIES` 与对应应用范围。显式 `TESS_BENCHMARK_DOWNLOAD_ONLY=1` 只准备模型，不改变用户偏好。

`python3 scripts/compare-asr.py <report1.json> <report2.json> --output <summary.json>` 汇总同语料结果；`scripts/check-interaction.sh` 包含学习与观察夹具，`python3 Tess/Checks/ASRBenchmarkCheck.py` 检查统计口径。
