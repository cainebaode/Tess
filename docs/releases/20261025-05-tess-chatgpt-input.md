# Tess build 27：ChatGPT 桌面输入诊断与兼容

日期：2026-10-25。版本：0.2.0 build 27。本轮为本机迭代；已安装，待用户实际输入验收。

后续用户测试：两次 ChatGPT Fn 会话均回退复制，build 27 自动输入未通过。诊断确认 `AXManualAccessibility` 返回 `-25205 / attributeUnsupported`，焦点输入框返回 `-25212 / noValue`；已转入 [build 28 原窗口输入兼容](20261025-06-tess-chatgpt-window-input.md)。本记录后文保留 build 27 当时的实施与检查状态。

## 问题与证据边界

用户反馈在当前 ChatGPT 桌面应用中按 Fn 识别后只显示复制。旧安装版为 build 26，辅助功能已授权，始终预览关闭。旧输入逻辑在无法确认输入框或原光标时统一复制，没有记录具体失败条件，因此无法仅凭旧记录确定失败属性。

本机 ChatGPT 的 Bundle ID 为 `com.openai.codex`。桌面工具明确禁止读取当前聊天应用界面，本轮没有绕过该限制、自动操纵该应用或代做真人 Fn 测试。已确认的实现缺口是 Tess 没有请求 Electron 暴露辅助功能信息。实现依据为 [Electron 官方辅助功能说明](https://www.electronjs.org/docs/latest/tutorial/accessibility/)，这不等于已证明用户本次故障只由该缺口引起。

## 本轮修改

- ChatGPT 切到前台时，提前请求 `AXManualAccessibility`，给渲染层准备输入框信息的时间；录音捕获前也请求一次。请求仅用于 `com.openai.codex`、`com.openai.chat`，不启用 VoiceOver、不改变系统授权；请求失败时仍执行原校验并保留错误码。
- 保留可编辑角色、可写状态、密码／终端保护、相同输入框和光标／选区校验；没有给 ChatGPT 增加无法确认输入框时的盲粘贴。
- 捕获及交付诊断区分权限、安全输入、前台应用、角色、可写状态、光标读取、输入框／窗口／选区变化，以及已发出粘贴事件和复制回退。浮层在复制回退时增加具体原因。
- 设置 → 权限与数据 → 自动输入诊断，可复制最近诊断。诊断写入用户数据目录的 `Diagnostics/input.json`，最多 100 条；记录时间、会话 ID、应用标识、build、固定状态码、AX 错误及有限角色信息，不记录录音、转写、正文或剪贴板内容，不上传。
