# Tess Mac 端优化方案

初稿：2026-10-26；更新：2026-10-27
状态：build 38 已实现并覆盖安装，准确率与人工体验待验收；第 7 节为下一轮实现方案，尚未开发。
范围：Mac 端基础识别质量与从人工纠正中学习。第 1–6 节保留 build 38 的原设计和验收背景；下一轮开发范围、优先级及通过标准以第 7 节为准。本文中的新指标是产品验收目标，不是已取得的结果。

**下一轮优先比较基础识别模型，同时建立“人工改字 → 确认纠正 → 下次识别提示”的反馈流程。** 正常听写不以用户预先维护词库为前提；个性化记忆不能代替基础模型质量，也不等于训练模型参数。当前只更新方案与开发交接，不修改产品代码。

上一轮同时优化识别辅助能力与实时转录浮窗。浮窗保留 build 38 的实现，下一轮仅做必要回归，不重新设计。Mac 工作与 [iPhone 产品验证](20261026-02-tess-iphone-prd.md)独立。

实施状态与实际对照结果见 [build 38 记录](../releases/20261026-03-tess-mac-optimization-build38.md)。常用词和上下文校正默认关闭；目前合成对照同时出现术语收益和汉字退化，本文中的真人准确率及等待指标尚未验收。

## 1 当前能力与问题定位

Tess 已有本地听写、两个提示词入口、文字服务配置、原文恢复、失败重试和复制回退。下一轮同时提高最终文字的可用性与录音过程中的可读性。

用户已提供三类真实反馈：`PRD → PLD`、`token → 偷看了`，以及本轮对话中的`语音输入 → 云输入`。前两类涉及字母及中英混说，第三类说明普通中文词组也会漏识别或误听，问题范围不能只限定为英文专有名词。

用户还反馈，录音浮窗可见文字偏少，感觉只有约两行，换行表现不自然。这是独立的展示体验问题。

| 问题 | 原因与边界 | 对应改进 |
| --- | --- | --- |
| 英文字母和专有名词识别错误 | 发音、噪声及词汇先验可能影响 PRD、PLD 等候选的选择 | 在识别阶段提供个人词库和简短背景 |
| 中英混说中的英文被写成中文 | 例如 token 被识别为“偷看了”；需要结合声音、语言切换和整句任务判断 | 单独评测混说场景，结合标准词、释义与整句校正 |
| 中文词组漏识别或误听 | 例如“语音输入”成为“云输入”；不能要求用户把普通中文都维护成词库 | 评测中文词组完整性，利用整句语境，并检查识别引擎本身的表现 |
| 实时文字暂时不准确 | 说到半句时，后文尚未出现，不能把中间结果视为最终结论 | 实时展示草稿，停止录音后定稿 |
| 最终输出没有按整句纠正 | 基础听写没有经过文字模型；整理模型也未必获得正确词汇及其含义 | 对完整转写做受约束的上下文纠错 |
| 浮窗显示范围、换行与阅读连续性 | 当前正文视窗固定较矮，每次文字更新都会滚到底部；具体换行问题需在界面复核 | 扩大正文空间，整理排版，区分跟随最新与回看模式，统一状态文案 |

“理解意思”不能等同于替用户猜测。例如，讨论产品需求时 PLD 可能应改为 PRD；讨论可编程逻辑器件时 PLD 应保留。同样，“模型调用的偷看了消耗”可能需要纠正为“token 消耗”，而“他偷看了我的笔记”必须保留。没有原始录音，不能仅凭错字断定是发音、语种提示、分块识别还是文字加工导致。

### 1.1 build 37 的代码切入点（历史基线）

- [ASRService.swift](../../Tess/Sources/ASRService.swift) 的 Qwen 调用只设置语言和输出长度，没有传入上下文。当前 Qwen 路径将较长音频按最多约 20 秒分块识别后拼接，未传递跨块的语义背景。
- 已编译的 [Qwen3ASR.swift](../../Tess/Vendor/SpeechSwift/Sources/Qwen3ASR/Qwen3ASR.swift) 中，`Qwen3DecodingOptions.context` 已进入模型提示词。因此可以先在当前依赖上验证，不必为接入上下文直接升级整个依赖库。
- [AppModel.swift](../../Tess/Sources/AppModel.swift) 在录音期间周期性识别录音快照，停止后重新识别，再按模式决定是否加工文字。Fn 基础听写走原文模式，跳过文字模型。
- [TextService.swift](../../Tess/Sources/TextService.swift) 已有保留术语、否定和事实的提示词；当前两个自定义入口会跳过旧的 `outputIssue`、`safetyWarnings` 检查。不能认为已有旧规则就覆盖了新纠错功能，也不应把旧规则直接套回全部自定义模板。
- [ResultView.swift](../../Tess/Sources/ResultView.swift) 已能查看原文、重新处理及重试识别。下一轮应复用这些入口。
- [HUDView.swift](../../Tess/Sources/HUDView.swift) 的转录正文是字号 13pt、固定高度 76pt 的滚动区域，未设置正文两行上限，但每次全文更新都会滚到底部。[HUDWindowController.swift](../../Tess/Sources/HUDWindowController.swift) 还将窗口限制为宽 380pt、最高 430pt。正文与窗口尺寸需要一起调整，不能只增加文字区域高度。

## 2 市面上可借鉴的方案

以下为截至 2026-10-26 的官方资料核对。公开功能说明只能证明存在对应机制，不能证明其对 Tess 的中文混合语料效果更好。

| 方案 | 已公开的能力 | 对 Tess 的价值与代价 |
| --- | --- | --- |
| Qwen3-ASR 开源模型 | 官方推理接口接受音频和 `context`，Tess 当前 Swift 实现也支持该参数。[官方源码](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_asr.py) | 最先验证；保留本地识别，改动集中。上下文提示不保证每次正确，也不能把云端接口能力自动套到本地模型上 |
| 阿里云 Qwen3-ASR-Flash | 非实时接口允许在系统消息中提供背景文本和实体词表；这不是任意角色指令。[官方 API](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference) | 可做停止录音后的云端识别对照；需要上传音频，并增加网络、费用和配置成本。文件识别的流式返回不等于实时音频输入 |
| 火山引擎豆包语音 | 提供热词、替换词和上下文；不同流式、非流式及二遍路径的支持范围不同，官方说明最终结果可受益于二遍处理。[热词与上下文](https://docs.volcengine.com/docs/DoubaoVoice/hot-words-and-context?lang=zh) | 可作为中文场景的云端候选；必须按实际选用接口验证，不能将某一路径的能力泛化到所有接口 |
| Wispr Flow 个人词典 | 区分词汇与纠正映射；官方明确说明替换规则是字面匹配，不理解语言语境。[词典说明](https://docs.wisprflow.ai/articles/4052411709-Teach-Flow-your-words-with-the-dictionary) | 可借鉴添加、编辑和纠错学习入口；不适合照搬全局 `PLD → PRD` 的硬替换 |
| 识别后使用文字模型校正 | 将完整转写、词汇和场景交给文字模型；Tess 已有可复用的文字服务调用基础 | 能利用整句语义，音频可继续留在本机；仅凭错误文本仍可能猜错，必须保留原文并限制修改范围 |

build 38 原定顺序为“当前本地模型加词库 → 可选的整句纠错 → 同语料云端对照”。2026-10-27 起调整为第 7 节的“基础模型对照 + 人工纠正反馈”，不再把手动词库作为整体准确率优化的前提。

## 3 推荐的纠错方案

### 3.1 个人词库先用于识别提示

在语音识别设置中增加“常用词”，每项包含标准写法、可选释义及可选常见误写。用户主动添加、编辑、停用或删除；初始词库为空，可通过示例说明填写方法。

| 标准写法 | 释义示例 | 常见误写示例 |
| --- | --- | --- |
| PRD | 产品需求文档 | PLD、P R D |
| token | 当前场景中的模型文本计量单位 | 偷看了等中文近音误写 |
| Tess | 当前语音输入产品名称 | Test、苔丝的其他误写 |
| SwiftUI | Apple 的界面开发框架 | Swift UI 的不一致写法 |

“常见误写”用于提供候选关系，不代表无条件替换规则。PRD 与 PLD 都可能正确时，以本句、当前明确场景及用户的纠正为准。送入 ASR 的词汇提示只包含标准写法与必要背景；误写形式留给后处理使用，避免把 PLD 等错误候选一并强化。

词库不能替代通用识别质量。对“语音输入 → 云输入”这类普通中文错误，需要观察同一句完整音频的识别与整句校正结果；不建立全局“云输入 → 语音输入”替换。中英混说评测同时比较自动语种与中文提示的实际效果，不预先认定某一种设置是根因或最佳方案。

首轮建议只取启用的少量词条，例如最多 50 项，并限制上下文总长度；这是 Tess 的初始产品限制，不是供应商接口上限。先使用用户明确维护的词汇和可选的一句话场景，不读取其他应用的聊天记录、屏幕或后台剪贴板。

录音开始时固定词库快照，实时预览和最终识别使用同一份配置。中途修改词库从下一次录音生效。先保留现有音频分块方式；跨块传递背景作为单独实验，避免前一块错字不断传播。

### 3.2 停止录音后再做整句校正

建议的数据流程：

```text
录音 + 个人词库
    ↓
本地 ASR：实时草稿 → 最终转写原文
    ↓ 用户已启用上下文校正时
完整原文 + 相关词条与释义 + 明确场景
    ↓
受约束的术语校正 → 用户选定的文字整理 → 最终结果
```

两个加工步骤是逻辑职责，首轮应尽量合并为一次文字模型请求，避免为每次输入串联多次服务调用。先以轻量整理入口验证，不覆盖用户保存的自由提示词。

纠错规则如下。

1. 词库只提供候选。结合完整句子判断，不因某个缩写不常见就替换；英文被写成中文近音词时，也要检查整句是否支持恢复英文。
2. 用户明确说“不是 PRD，是 PLD”时，最终保留 PLD；引用别人说错的话也不能替用户改写。
3. 数字、金额、日期、路径、代码标识、否定、条件和承诺保持原意；明确的口述自我修正另行处理。
4. 不扩大缩写、不补充事实、不回答转写中的问题。需要写“产品需求文档（PRD）”时，应来自用户要求或所选模板。
5. 没有足够依据时保留原词。存在词库内的具体候选时，可在结果面板提供选择，不在正文里插入猜测说明。

普通中文纠错需要单独约束。对于缺少明确词条依据的“云输入”，模型可以提出“语音输入”候选，但首轮不能仅凭模型自评分自动采用；用户明确纠正或在评测中验证过的窄范围规则才可自动生效。评测记录应区分“识别器已正确输出”“自动纠正成功”“需用户确认”，不能把展示候选算作自动解决。

内部应保留“ASR 原文、处理结果、术语修改清单”。修改清单至少包含原片段、目标片段和依据类别，用于检查与撤销；模型返回的自评分数不能当作可靠置信度。结构化结果无法解析、修改片段无法对应或校验不通过时，保留原文并提供重试。

新增校正应有独立的本地检查：核对修改片段确实存在、目标来自允许候选或明确口述纠正，以及受保护的数字和路径等未意外改变。自由润色与术语替换分别评估，避免用“所有文本必须几乎不变”破坏现有翻译和摘要模板。

### 3.3 三个语音入口的行为

| 入口 | 建议默认行为 | 用户可选择的增强 |
| --- | --- | --- |
| Fn 基础听写 | 保持本地转写；用户启用词库后使用词汇提示 | 单独启用结束后的上下文校正；启用时说明将发送转写文本及相关词条 |
| 自定义入口 1 和 2 | 保留现有快捷键、模板与用户编辑 | 对所选入口启用上下文校正，先校正术语再执行模板 |
| 未配置文字服务或离线 | 本地听写及词库提示继续可用 | 保留 ASR 原文，明确本次未进行文字模型校正 |

开启词库后的“原文”仍是识别器给出的转写，不应被描述为未经推断的录音真值。

### 3.4 实时显示与失败恢复

- 录音中显示真实转写草稿，不对每个不稳定片段调用文字模型；停止后展示最终文本。
- 进入文字加工后可立即选择“使用原文”；新增上下文校正建议以 8 秒为总等待上限，超时保留原文。该上限只针对新增纠错流程，不顺带改变所有自定义任务的超时规则。
- 最终文本只交付一次。用户已选择原文、取消、重新录音或移动输入目标后，迟到的纠错结果不能继续覆盖或插入。
- 复用当前结果面板提供原文对照、再次复制和重试。用户主动修改错词后，可点“记为常用词”；首轮不后台监控所有输入，也不自动把一次修改永久学成规则。

## 4 实时转录浮窗优化

### 4.1 目标与现状

让用户在说话时读到有意义的上下文、看清最新内容，并能稳定回看。继续采用小浮窗，但把转录正文作为主体，减少状态说明和音量装饰对正文空间的挤占。

已核实的实现问题是正文视窗固定为 76pt，以及任何转写更新都会触发滚到底部。用户看到约两行的具体原因仍要结合实际窗口、字体排版与滚动位置确认，不能把它直接归因于代码写死两行。换行也需区分视觉软换行、识别结果自带换行及窗口裁切。

### 4.2 正文空间与排版

| 项目 | 建议行为 | 验收重点 |
| --- | --- | --- |
| 可见内容 | 默认预留约 6 行完整正文，视窗以约 130–150pt 为原型起点；较长内容在区域内滚动 | 正常笔记本屏幕可看到连续语意，首尾行不被截成半行 |
| 宽度与字号 | 正文有效宽度以至少 340pt、字号 14–15pt 为原型起点，设置舒适行距 | 中文夹 token、PRD 等英文时易读；不靠缩小字体硬塞内容 |
| 浮窗布局 | 状态与录音反馈保持紧凑，停止、取消和计时位置稳定 | 文本增加或阶段切换时，按钮不跳动、不被挤出窗口 |
| 窗口尺寸 | 同步调整正文和窗口约束，保留顶部锚点，并限制在当前屏幕可用区域内 | 不能增加正文后仍被旧的 430pt 窗口上限裁掉；不遮挡菜单栏或越出屏幕 |
| 长文 | 保存完整转写，通过滚动回看；完成后可打开已有结果面板 | 不以只保留末尾若干字符的方式伪装成完整记录 |

正常窗口下，英文短词和缩写按词边界换行，避免把 token 或 PRD 拆成逐字母竖排；中文按自然排版换行。超长路径、URL 或代码标识允许视觉折行，但不往实际文本中插入换行、空格或省略号。原文明确存在的段落换行保留。

以上尺寸用于第一版布局验证，最终以实际屏幕上的阅读效果确认。沿用现有材质、颜色和品牌，不扩展为另一轮整体视觉改版。

### 4.3 更新与滚动行为

1. 默认跟随最新内容，让最新一句完整可见；底部保留必要内边距，避免最新行贴边或只露出一部分。
2. 用户向上滚动后暂停自动跟随，新增转写不再把视图拉回底部。显示轻量的“回到最新”，点击或主动滚回底部后恢复跟随。
3. 部分转写可能修订前文，应按最新完整快照更新，不把每次快照重复追加成新段落。尽量保留当前阅读位置，不能假定某段此前出现过就永远不变。
4. 文字更新不触发整窗缩放、重复淡入或高度跳动；正文区域维持稳定，只做必要的文本更新和滚动。
5. 从录音进入最终识别、文字整理时，保留当前可读文本，再替换为对应阶段的真实结果；不短暂清空，也不把尚未完成的整理结果标为终稿。
6. 浮窗查看、滚动和控制操作不主动抢走原输入框焦点；原有输入目标保护继续有效，目标确实变化时仍明确提示复制回退。

### 4.4 状态与展示文案

状态说明和转录正文分区，正文只放识别或整理所得文字。标题简短说明正在做什么，不将临时草稿称为最终结果。

| 时机 | 主状态 | 正文区标签与提示 |
| --- | --- | --- |
| 录音已开始，尚无文字 | 正在听 | 标签“实时转录 · 未定稿”；占位“说话后，文字会显示在这里。” |
| 已收到声音，首段仍在识别 | 正在听 | 占位“正在生成转录…”；有草稿后直接展示草稿 |
| 录音进行中 | 正在听 | “实时转录 · 未定稿”；可持续修订的真实文本 |
| 实时预览暂时失败 | 仍在录音 | 保留上一段文字，提示“实时转录暂不可用，结束后将识别完整内容。” |
| 用户停止，正在最终识别 | 正在生成最终转录 | 保留最新草稿，不清空 |
| 文字模型加工 | 正在整理文字 | 显示已有转写，明确“整理中”；允许使用原文 |
| 回看早先内容 | 主状态保持真实录音或处理状态 | 显示“回到最新”；新内容到达不强制滚动 |
| 已完成交付 | 已输入／已复制 | 按实际交付结果显示；复制时提示“回到输入框按 ⌘V”，保留查看结果入口 |

完成时，结果面板、剪贴板及实际输入的内容保持一致。英文界面提供对应简短文案，并复核较长英文状态不会挤压正文和操作区。

### 4.5 本轮优先级与实施边界

| 优先级 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 | 建立同录音对照集并核对基线 | 能分清识别错误、纠错收益与误纠正，而非只比较几条漂亮示例 |
| P0 | 接入本地词库上下文并评测中英混说 | PRD、token 等词改善，普通中文及正确缩写不退化 |
| P0 | 可选整句纠错及原文回退 | 区分 PRD／PLD、token／偷看了及语音输入／云输入；模糊内容不硬改 |
| P0 | 浮窗正文布局与换行 | 增加完整可见行，改善中英文排版，正文与操作区不裁切 |
| P0 | 实时阅读、滚动与文案 | 回看不被拉走，阶段转换不清空或误标终稿，取消和交付时序正常 |
| P1 | 纠错记忆入口、词库编辑体验 | 用户可以修正、停用和撤销自己的规则 |
| P1 | 处理真实发现的性能与兼容问题 | 首次等待、耳机切换、休眠恢复等有复现问题再做针对性修改 |
| P1 | 新用户试用与版本发现 | 3–5 人可独立完成首次输入；按反馈决定是否增加轻量更新提醒 |

本轮调整浮窗的阅读布局与文案，延续现有视觉风格、Bundle ID、签名身份、设置、权限和模型。截图能力按现状维护。以上为实施建议；用户后续已授权 build 38 本机迭代，实际实现与未完成的质量验收以对应记录为准。

## 5 如何验证真正解决了问题

### 5.1 使用同一组录音做对照

建议准备 80 条人工标注录音，分为开发与保留评测两组，各 40 条；保留组不参与调提示词。真人口音、内置麦克风、耳机及少量环境噪声应分布在各类样本中，合成语音只作补充。

| 样本类别 | 数量 | 重点 |
| --- | --- | --- |
| 缩写与中英混输 | 20 | PRD、API、SDK 的读法，以及中文句子中的 token 等英文词 |
| 中文词组完整性 | 15 | “语音输入 → 云输入”等漏字或近音错误，含自然连读 |
| 产品名与人名 | 10 | 有词库与无词库时的差异 |
| 歧义与正确词保护 | 15 | 真正的 PLD、“偷看了”和“云输入”，陌生但正确的词与词库冲突 |
| 自我修正及事实约束 | 10 | “不是……是……”、否定、日期、数量、路径 |
| 较长口述 | 10 | 20 秒以上跨块内容、前后补充语境、撤回要求 |

至少比较 A 当前版本、B 本地词库、C 本地词库加整句纠错。需要引擎对照时，再用同一语料比较阿里云或豆包；仅上传用户明确允许用于云端评测的录音。

### 5.2 建议的通过标准

| 指标 | 建议门槛 |
| --- | --- |
| 术语错误 | 保留组术语错误次数较基线减少至少 40%；同时报告错误数和术语总次数 |
| 中文词组与中英混说 | 分别报告中文词组漏字、英文被转成中文近音词的数量；加入词库后两类均不高于基线，并单列本轮三个例子的改善情况 |
| 误纠正 | 保留组中原本正确的术语及中文表达被改错为 0；真正的 PLD、“偷看了”和“云输入”能保留 |
| 事实完整性 | 数字、否定、路径及有效需求出现非预期改变为 0 |
| 普通转写 | 普通中文字符错误率不高于基线 0.5 个百分点以上 |
| 新增等待 | 对 10–30 秒录音，开启校正后的额外等待 p95 目标不超过 2 秒；注明设备、网络、模型和是否冷启动 |
| 中断与交付 | 取消后输出、重复插入、迟到结果覆盖均为 0；失败时原文可取回 |

这些是小规模选型门槛，不是对所有场景的准确率承诺。若减少错词却增加误纠正，应收紧自动修改范围，而不是继续放宽提示词。

关键验收例子：

| 转写与上下文 | 预期行为 |
| --- | --- |
| “给移动端写一份 PLD，包含用户场景和需求”，词库有 PRD＝产品需求文档 | 最终为“给移动端写一份 PRD，包含用户场景和需求。” |
| “这颗 PLD 需要重新编程” | 保留 PLD |
| “把 PLD 发给我”，没有更多信息 | 保留 PLD，不猜测 |
| “不是 PRD，是 PLD” | 保留最后明确选择的 PLD |
| “这次模型调用的偷看了消耗是多少”，词库含 token 且语境为模型计量 | 最终为“这次模型调用的 token 消耗是多少？” |
| “他偷看了我的笔记” | 保留“偷看了”，不替换成 token |
| “每次云输入时，这个录音浮窗显示的转录文字太少”，此前已明确讨论语音输入 | 识别阶段优先正确输出“语音输入”；若原文仍为“云输入”，校正阶段给出候选，自动采用须符合已验证规则 |
| “你看，又听成云输入了，而不是语音输入” | 保留两个被比较的词，不把引用的错误词也改掉 |
| “不是云输入，是语音输入” | 保留用户最终明确选择的“语音输入” |
| “我们讨论的是云输入方案，不是语音输入” | 保留对比关系，不全局替换“云输入” |
| “这份 PLD 文件在 /tmp/PLD.json”且语境指产品需求文档 | 可按依据校正文中的术语，文件路径必须原样保留 |
| “周三交，哦不周四，预算不要改” | 保留周四和“预算不要改”，不补预算数额 |

### 5.3 浮窗展示验收

使用真实文本覆盖短句、约 200 字及 1,000 字以上的转录，包含 token、PRD、英文句子、中文标点、自然段和长路径；另用连续录音确认更新节奏和实际手感。

| 场景 | 完成标准 |
| --- | --- |
| 默认正文布局 | 正常笔记本屏幕可见约 6 行完整正文，首尾行、状态与停止／取消按钮无裁切 |
| 中英文换行 | token、PRD 等短词不被逐字母拆行；中文不异常留白；超长标识只视觉折行，实际文本不变 |
| 连续转录与前文修订 | 最新文字可见，不重复追加同一快照；窗口和按钮位置稳定，无反复清空闪烁 |
| 手动回看 | 向上滚动后连续到达的新文本不拉回底部；“回到最新”可恢复跟随 |
| 停止、整理与完成 | 草稿到终稿的阶段清楚，处理中保留可读文字，最终内容与交付结果一致 |
| 原输入位置 | 操作浮窗不主动抢焦点；确实改变输入目标后按既有规则回退，不重复输入或发送 |
| 小屏与英文界面 | 窗口保持在可用屏幕内，较长状态说明不挤掉正文及操作区 |

用必要的布局与状态检查确认技术行为，再由用户进行一次短句、一次较长口述和一次滚动回看的集中体验；不以静态截图代替真实转录验收。

## 6 build 38 的执行顺序与交付（历史方案）

1. 分别固定识别语料和展示场景，记录当前错词、等待、可见行数、换行及滚动行为。
2. 展示侧完成浮窗正文空间、换行、滚动和状态文案调整，按第 5.3 节独立验收，无需等待模型选型。
3. 识别侧接入本地上下文，评估中英混说及中文词组完整性；通过后加入词库操作界面。
4. 加入可选整句纠错、差异记录和原文回退，复测所有入口及取消时序。
5. 若识别效果仍不足，比较云端候选，再决定是否增加引擎选项。
6. 按[项目迭代流程](../iteration-and-release.md)递增 build、必要检查和本机覆盖安装，分别记录两条主线的用户体验结论。

验收记录至少保留选定方案、语料分组、错误对照、延迟、资源占用、回退结果、浮窗布局与阅读行为以及真人反馈。功能迭代与正式安装包交付按既有流程分开进行。

## 7 下一轮：基础模型与人工纠正学习

### 7.1 目标、现状与首版边界

用户希望普通中文、中英混说和缩写更准确，并让日常手动改字帮助后续识别，而非另行维护大量词条。下一轮交付两个可分别验证的结果：一份本地模型对照结论，以及可使用、可撤销的个人纠正记忆。

2026-10-27 已核对的源码现状：

- `ASRService` 已支持 Qwen3-ASR 0.6B、1.7B（MLX 4-bit）及 Whisper large-v3-turbo（CoreML）；接入选项不代表模型已下载或实际效果已验证。
- build 38 已把 `SpeechVocabulary.asrContext` 传给 Qwen；Whisper 路径尚未使用该提示。8 条合成录音同时出现术语改善和汉字退化，不能据此宣称整体更准。
- `ResultView` 可编辑结果，`AppModel.editOutput` 只保存改稿；“记为常用词”用首尾差异预填编辑框，还没有自动获取外部改稿、判断纠正或累积学习的流程。
- `DeliveryService.Outcome.attemptedPaste` 只表示已尝试粘贴，不证明内容已进入输入框。微信／ChatGPT 的兼容目标可能只有窗口身份，无法读取编辑文本。
- `SavedResult` 有独立 ID、ASR 原文和输出，最近结果按 24 小时清理；录音用于当前识别／重试，不是持久训练集。

| 首版要做 | 本轮不做 |
| --- | --- |
| 对照现有本地模型；先排查音频、语种和切块影响 | 不先认定更大模型必胜，不直接替换用户所选模型 |
| Tess 结果页、可验证的外部输入框获取改稿；不支持时主动提交改稿 | 不承诺所有应用无感学习，不监控所有键盘／剪贴板／屏幕 |
| 提取差异、确认纠正、保存本地记忆、用于后续 Qwen 识别、撤销及清空 | 不把润色或改主意学成识别规则，不做全局错词替换 |
| 沿用 build 38 的浮窗、快捷键、模板与文字服务行为 | 不新增云端 ASR、账号、跨端同步，不微调模型，不新增日常录音持久化 |

### 7.2 基础模型先做同录音对照

首选比较已有的 Qwen3-ASR 0.6B 与 1.7B；Whisper large-v3-turbo 作为另一种已有引擎的对照。基础对照关闭手动词库、个人学习及文字模型加工，使用相同 WAV、相同参考文本和相同分组。语种“自动／中文”作为单独变量，在开发组比较，不与换模型、加提示同时改变。记录实际转换模型版本、量化、权重摘要和 Swift 推理实现，不能把官方 BF16 成绩套到 Tess 的 4-bit 版本。

Qwen 官方公开评测中，1.7B 在多项中文数据集优于 0.6B，因此优先测试；这只是选型依据，不能代替本机测量。[官方评测](https://github.com/QwenLM/Qwen3-ASR#evaluation)

如果本地候选仍不足，记录后续候选而不在本轮扩大集成：Fun-ASR-Nano 支持中文、英文及多种中文口音；Qwen3-ASR-Flash 可作用户允许上传录音后的云端对照。当前没有证据证明任一候选对本用户最好。[Fun-ASR 官方项目](https://github.com/QwenAudio/Fun-ASR)、[Qwen 云端接口](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)

发现录音采样、首尾截断或 20 秒切块边界的可复现问题时，先修对应问题并重测基线，不同时重写音频管线。模型下载沿用现有路径，不删除已安装模型、不更换签名或改写用户选择。准确率不足时保留当前默认，给出实际推荐与代价；不存在“必须选出新模型”的通过条件。

### 7.3 用户操作：从改字产生记忆

在语音识别设置增加一个默认关闭的“从我的纠正中学习”。开启后，同时允许采集本次听写的改稿和使用已确认的个人记忆；关闭后立即停止采集，并从下一次录音起停用个人记忆。关闭不删除已确认记录，另有“清空已学习内容”。旧“常用词”及其开关保留为手动管理入口，不要求用户同时打开两个开关才能使用学习结果。

典型流程：

1. 用户正常听写，Tess 保留本次 ASR 原文与实际交付文本两个不可变基线。
2. 用户在结果页或支持的目标输入框把“写一份 PLD”改为“写一份 PRD”；停止编辑约 1 秒后，后台计算差异，不影响打字或重新插入文字。
3. 首次发现新纠正，只在最近结果里显示“PLD → PRD：这是听错了吗？”以及“记住／忽略”。不弹模态窗口、不抢焦点；用户无需重填词条和释义。候选不是已学习内容。
4. 点击“记住”后，本地保存正确写法与必要范围；下一次录音将相关正确词提供给 Qwen。已确认的同项不重复询问，一次会话不因多次通知重复计数。
5. 用户在“已学习内容”中查看、停用、删除；保存后提供撤销。自动提取差异不等于能自动判断用户意图，首版不按“重复修改三次”等次数规则偷偷激活新记忆。

首版自动生成候选仅限**纯听写且未经过上下文校正或其他文字加工**的结果。翻译、摘要、润色、AI 指令及人工粘贴文字不反向生成 ASR 纠正；这些场景仍可主动添加常用词。已有学习记忆可用于任一入口的本地识别阶段，但不能从随后生成的文字自我强化。

### 7.4 怎样可靠获取修改结果

| 来源 | 首版实现 | 不能确认时 |
| --- | --- | --- |
| Tess 结果页 | 保存编辑开始前的交付文本；`editOutput` 只更新当前改稿，停止编辑后计算差异；复制、继续编辑和撤销均关联同一结果 ID | 不从旧版本候选学习；确认前重新核对当前文本 |
| 普通可访问输入框 | 仅在个人学习开启时，对本次目标建立短期观察；先验证真实插入，再读取这段文字的变化 | 属性／通知不支持、位置不唯一或范围变化时停止观察，保留正常输入能力 |
| 微信、ChatGPT 等兼容输入，或只有“已复制” | 最近结果提供“提交改好的文字”：用户主动复制刚改好的整段，在 Tess 对照框内粘贴，确认对应哪次结果 | 不通过模拟全选／复制、屏幕 OCR 或后台剪贴板轮询获取全文 |

外部输入框按以下顺序处理，不绕过既有输入保护：

1. 只处理可读取文本、选区和可编辑状态的非安全输入框。临时记录进程、窗口／元素身份、结果 ID、插入前选区与必要邻近锚点；这些数据不写入普通诊断日志。
2. 粘贴前后做有限次数回读，最长 1 秒。只有实际文本能按原选区唯一解释为插入／替换了交付文本，才建立观察范围；`attemptedPaste`、复制回退或碰巧搜到相同句子都不算成功证据。
3. 仅观察这个元素，最长 120 秒；使用文本变化通知并防抖约 1 秒。支持读取但不支持通知时，首版直接提供主动提交入口，不新增全局轮询。Apple 的接口允许返回属性或通知不支持，不能假设所有输入框具备能力。[属性读取](https://developer.apple.com/kr/documentation/applicationservices/1462085-axuielementcopyattributevalue)、[通知注册](https://developer.apple.com/documentation/applicationservices/1462089-axobserveraddnotification?changes=l_4)
4. 每次用边界／锚点验证仍是本次插入的范围；若改动跨出范围、重复文本无法定位、元素重建或失效，结束采集。AX 的 UTF-16 范围与 Swift 字符索引要显式转换，覆盖中文、组合字符和 emoji。若 API 只能返回整个字段，全文仅用于内存定位，超过 8,000 字则放弃自动采集；只保留本段及必要短上下文。
5. 输入框失焦、应用／窗口切换、下一次录音、超时、权限失效、关闭学习或退出时解除观察。观察状态与粘贴前的 `InputInteractionGuard` 分离，不能让“用户开始改字”触发新的粘贴或破坏剪贴板恢复。
6. 停止前已稳定取得的差异可以作为待确认候选；字段清空不能被当作“用户纠正为删除全文”或“已经发送成功”。撤销回到交付文本时取消候选。迟到回调必须匹配会话、结果 ID 与修订号；不得修改新一轮结果。

主动提交只接受用户明确指定的最近结果及对应整段改稿，不猜测从外部选择的几个字属于哪次录音。选择任意片段的全局快捷键留到后续，避免首版增加配对歧义。

### 7.5 怎样区分听错、润色与改主意

使用本地差异算法，不为每次修改调用文字模型。不能继续以单一公共前后缀把所有中间内容当成一个错词；需能识别多个局部差异、重复片段及字符边界。算法负责找出候选，最终“这是一次识别纠正”由用户确认。

| 改动 | 处理 |
| --- | --- |
| PLD → PRD、偷看了 → token，周围句子稳定 | 提取小范围候选，显示完整句子供确认；不单凭字符串相似度认定是听错 |
| 云输入 → 语音输入 | 作为普通词组纠正候选；确认后仅提示正确词，不建立全局替换 |
| 周五 → 周六、100 → 1000、需要 → 不需要、路径／URL／代码标识变化 | 首版不进入自动学习候选，即使差异很小；仍保留用户真实改稿 |
| 增加新观点、调整语序、大段删改、改写语气、仅标点／空白变化 | 当作内容编辑或格式调整，不生成识别记忆 |
| 一处改动对应多个位置，或同一误写有不同正确形式 | 不猜对应关系、不合并；需要用户在对照中明确选择，否则忽略 |
| 翻译／整理结果、文字模型给出的候选、模型自己的纠错 | 不作为人工反馈样本；禁止生成结果循环写入个人记忆 |

首版把“小范围”限制为每处改前和改后均不超过 32 个字符、一次最多 3 处，且能定位未改动的邻近文本；超限转为手动查看，不拆成大量词条。这些是控制误收的实现边界，不是置信度分数。用户点击“记住”时再次验证显示的基线、改稿和修订号，不能把已经撤销的修改保存进去。

### 7.6 记忆如何用于后续识别

已确认记忆记录正确写法、误写、可选简短说明、来源和适用范围。默认只对原目标应用生效；在 Tess 内编辑的结果沿用其原目标应用，无法确定时必须让用户选择“所有应用”或不启用。管理页允许主动改为所有应用。应用范围只是减少不相关提示，不能被描述为理解了该应用所有语境。

- 录音开始时固定一次提示快照：启用的手动常用词 + 个人学习已开启且适用的已确认记忆，去重后最多 50 项、总长不超过现有 2,000 字。手动词优先，剩余按适用范围及最近确认时间选择；超限明确显示本次未包含，不静默删除记录。
- ASR 只收到正确写法和用户确认的短说明，不能收到误写映射、历史改稿全文或其他应用内容。保留真实 PLD、“偷看了”“云输入”的能力仍须评测；提示也可能引入偏差。
- 同一误写在同一范围内出现不同纠正时，标记冲突，不以最近一次覆盖旧项；冲突项暂停自动提示，待用户明确范围或停用其中一项。
- 学习开关控制采集和已学习提示，旧常用词开关只控制手动词；二者独立。关闭、删除或撤销后，下一次录音的提示中必须不存在对应项；当前录音继续使用已固定快照。
- 首版个人记忆只用于本地 Qwen 识别，不自动并入 `TextService` 的远端纠错材料，也不改变现有文字服务的开关。Whisper 保持当前能力，界面说明“此模型暂不使用个人学习提示”，不暗示已经生效。

用户感知应是“记住了这次用词，下次识别时参考”，不能写成“模型已经训练完成”“以后一定不会错”。

### 7.7 数据与代码落点

只新增满足上述流程的数据，不建设通用训练平台。字段可按现有代码风格实现，但必须保留以下语义：

| 数据 | 必要内容与生命周期 |
| --- | --- |
| 本次听写基线 | 结果／会话 ID、ASR 原文、不可变交付文本、模式和是否文字加工、原目标应用、模型／提示版本；不以可变 `output` 充当基线，随最近结果按 24 小时清理 |
| 待确认差异 | 基线与改稿修订号、局部改前／改后、必要句子、来源及时间；首版只保留最近结果的一组候选，被新结果替换或到 24 小时即清理；不重启恢复外部观察 |
| 已确认记忆 | ID、正确词、误写、短说明、应用范围、启用／冲突状态、确认时间与去重信息；本地持久化，可停用、删除、撤销、清空；最多 50 条，到限后提示管理，不覆盖旧项 |
| 临时外部观察 | AX 元素、进程／窗口、范围和定位锚点，仅内存，随观察结束释放；不保存完整输入框或聊天历史 |

建议新增一个小型本地学习存储（如 `speech-learning.json`），复用 `LocalStore` 的原子写入、目录 0700／文件 0600 及损坏恢复机制；已确认记忆只存一份，不复制到 `SpeechVocabulary.words`。提示在每次录音开始时组合生成。待确认内容可随 `SavedResult` 保存；新增 Codable 字段需兼容旧文件缺失，不重置偏好。

“清空已学习内容”同时清除待确认候选与学习存储的恢复副本，不能重启后从备份重新学回。关闭学习立即销毁观察与待确认候选，但保留已确认记忆供以后启用；删除／撤销也清除相应待处理项。普通日志只记录状态与计数，不记录录音、转写、词条或输入框全文。用户主动生成的评测材料留在本机忽略目录，不进入源码 Git。

| 代码位置 | 最小修改方向 |
| --- | --- |
| `AppModel.swift`、`Localization.swift` 的 `SavedResult`／`AppPreferences` | 保存不可变基线和来源，连接编辑、确认、取消、过期与会话隔离；开关缺失默认关闭 |
| `ResultView.swift`、`SpeechVocabularyView.swift`／`SettingsView.swift` | 候选确认、主动提交改稿、学习开关及记忆管理；复用现有卡片与编辑器，不增加独立管理窗口 |
| `DeliveryService.swift` | 向会话提供可验证的插入信息；新增小型观察组件即可，不改现有兼容输入与剪贴板事务语义 |
| `SpeechVocabulary.swift`、`ASRService.swift` | 将手动提示与已确认记忆按开关／范围组合，仅送入 ASR；实时预览、最终识别和重试使用同一快照 |
| `LocalStore.swift` 及现有存储检查 | 复用持久化能力，覆盖迁移、过期、撤销、清空与恢复副本，不扩展无关存储功能 |
| `ASRBenchmark.swift` 与对应检查脚本 | 复用显式语料入口；补充样本来源、开发／保留分组和提示快照。当前报告固定写“合成语音”，必须按真实来源记录；内部入口继续不进入交付版 |

### 7.8 验证：功能可用与准确率改善分开

**功能检查**使用本地夹具验证，不依赖真实 API Key，也不长时间自动操作用户应用。

| 检查组 | 必须覆盖 |
| --- | --- |
| 差异与确认 | 多处修改、中文／英文／emoji／组合字符、重复短语、仅标点、大段改写、日期／数字／否定／路径、确认前继续修改、撤销还原、同会话重复通知 |
| 来源与范围 | 纯听写可提取；翻译、文字加工及人工粘贴不可自动学习；不同应用、未知应用、同词冲突不串用；未确认候选永不进入提示 |
| 外部采集 | 验证成功的插入才观察；粘贴未生效、只有复制、同文重复、替换选区、通知不支持、失焦、元素重建、字段清空、超过 120 秒、8,000 字上限及迟到回调 |
| 生命周期 | 开关关闭／缺失、重启、旧 JSON、存储失败、24 小时过期、停用、删除、撤销、清空与损坏恢复副本；不改变已有设置和词条 |
| 识别与输入回归 | 提示独立开关、固定快照、超限／冲突处理、Whisper 说明；不向文字服务发送学习记录；取消后无插入、无重复交付，剪贴板保护与浮窗回看仍正常 |

**准确率对照**沿用第 5.1 节的 80 条真人标注录音与 40／40 开发／保留分组。近重复录音按原句归组，个人记忆只从开发组的真实纠正建立；保留组使用不同录音与句子，包含相同术语的新语境和反例。冻结记忆、模型与参数后才跑保留组，不能看过结果后继续调提示并把同一组当独立验收。

对照至少分为 A：0.6B 无提示；B：1.7B 无提示；C：选定模型 + 从开发组确认的记忆。另列 Whisper 无提示结果。比较 C 时必须有同模型、同参数、不开记忆的对照，不能把换模型收益算成学习收益。每个条件单独进程运行，冷启动单列，热推理重复 3 次；重复次数只用于测延迟，不当作新增独立语料。记录字符错误率、术语错误数／总次数、漏字、正确词被改错数、结束等待 p50／p95、峰值内存及失败次数。

| 判断 | 下一轮目标与决策 |
| --- | --- |
| 基础模型值得推荐 | 保留组总体字符错误率相对 0.6B 下降至少 15%，普通中文子集恶化不超过 0.5 个百分点；若基线几乎无错或样本不足，报告原始计数，不强算显著收益 |
| 个人记忆确实有效 | 与同模型无记忆相比，保留组术语错误减少至少 40%；普通中文恶化不超过 0.5 个百分点，歧义反例中新出现的误纠正为 0；不得只用 PRD 一例宣称达标 |
| 等待与稳定性 | 10–30 秒录音，新基础模型热推理 p95 相对基线增加不超过 1 秒；同模型开启记忆后的额外 p95 不超过 200 毫秒；超过预算则报告精度／等待取舍，不强改默认 |
| 人工体验 | 用户正常改字后能看到正确候选、确认后下次可用，停用／撤销有效；不支持的应用可主动提交，不需要维护整套词库；由用户确认，自动检查不代替 |

以上门槛是本轮筛选目标，不是准确率保证；为基础模型、学习效果、技术行为和人工体验分别记录状态。没有足够真人语料时，可以完成代码、隔离检查及本机试用安装，但将准确率标为“未验证”，不能用合成录音冒充真人或宣称越用越准。没有原始录音的改稿也不能直接进入 ASR 评测集。

### 7.9 真正微调留到后续阶段

Qwen 官方提供以音频与转写配对数据微调的流程，属于更新模型参数，需要训练和独立评测。[官方微调说明](https://github.com/QwenLM/Qwen3-ASR/blob/main/finetuning/README.md)

首版不保存日常录音，也不训练。后续若用户明确启用样本保留，再设计“原始录音 + 对应的忠实正确转写 + 来源／授权 + 模型版本”的样本库，明确保存期限、删除与导出；润色后的文章不能作为逐字转写标签。积累可靠数据后再决定训练方式、设备或服务，保留未参与训练的评测组和可回退模型。仅有文字纠正可支持个人词汇记忆，不能证明模型已学会用户发音。

### 7.10 开发顺序与交接要求

1. **核对基线并准备对照**：读 README、实际 AGENTS、迭代流程、开发状态与 build 38 记录，确认当前源码／已安装版本及未提交改动；复用已有模型与 benchmark，建立真实语料入口和基线记录。
2. **先完成本地反馈流程**：结果页和主动提交改稿 → 差异候选 → 人工确认 → 本地记忆 → 下一次 ASR 提示；通过来源、歧义、迁移与撤销检查。模型评测缺少语料时，不阻塞这部分开发。
3. **接入受限外部观察**：实现经过插入验证的单输入框观察，覆盖生命周期和兼容回退；用本地夹具验证，用户集中验收实际应用。不能以兼容应用无法观察为由放弃可用的主动提交路径。
4. **对照与交付**：完成可取得语料的模型及记忆对照，如实标记缺口；按[迭代流程](../iteration-and-release.md)递增实际 build、必要检查、沿用原签名覆盖安装，保留配置、权限、模型和引导，更新开发状态与本轮验收记录。

只修改本轮 Mac 需求涉及的代码；保留 build 38 浮窗及已有功能，避免覆盖其他 agent 的未提交修改，尤其不修改 `Tess-iPhone/`。不顺带公证、DMG、公开发布或同步 GitHub。最终交付包含实际安装版本、可用／不支持的采集路径、模型与学习对照结论、检查结果和一份简短人工验收清单；未验证的准确率明确列出。
